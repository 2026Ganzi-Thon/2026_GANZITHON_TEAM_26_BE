**규칙**
- `main`: 배포 브랜치. 직접 푸시 금지(pre-push 훅이 막음), `dev`에서 PR로만 머지
- `dev`: 개발 통합 브랜치. 기능 브랜치는 여기서 따고, 여기로 PR
- 기능 브랜치: `{타입}/#{이슈번호}-{간단한-설명}`

**예시**

`feat/#12-cheer-send`

`fix/#20-map-count`

**작업 순서**
1. 이슈 생성 (템플릿: Feature / Bug / Config)
2. `dev`에서 브랜치 생성 → 작업 → 커밋
3. PR 생성 (base: `dev`) → 리뷰 → 머지
