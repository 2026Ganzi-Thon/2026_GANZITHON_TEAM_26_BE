# ITR-REST 기능 명세

## ITR-REST-001 함께 쉬는 방

**추후 구현 - P1**

**트리거**
'함께 쉬기' 선택(패치 받기 완료 후) 또는 함께 쉬는 방 직접 진입

**사전조건**
로그인 상태, 패치 받기 완료

**입력**
없음

> 2026-11-13 팀 결정: 15분 타이머는 **스톱워치**(입장 후 경과 시간 표시, 종료 시점 없음)로 바뀌었고, 인원은 감정과 관계없이 **방 전체 동시 접속 인원**으로 집계합니다.

**처리 로직**

1. 입장 시 패치 받기 완료 여부를 확인하고 입장 시각을 기록한다. 퇴장 후 10분 안에 다시 들어오면 기존 입장 시각을 이어 쓴다.
2. 방에 머무는 동안 30초마다 받는 신호로 접속 여부를 판단한다. 최근 60초 안에 신호를 보낸 사용자를 현재 인원으로 본다.
3. 현재 인원은 감정과 관계없이 방 전체 동시 접속 인원(채팅 없음)을 익명으로 집계한다.
4. 입장 시각부터 경과 시간을 스톱워치로 표시한다(종료 시점 없음).
5. '나가기' 클릭 시 퇴장 처리 후 [[ITR-MAP-001]] 온기 지도 인원 표시 화면으로 이동한다. 탭을 닫거나 다른 탭으로 전환해도 퇴장 처리된다.

**출력**
현재 인원(익명), 입장 시각(스톱워치 계산 기준)

**예외 케이스**

| Status Code | Status Name  | Description                                                                            |
| ----------- | ------------ | -------------------------------------------------------------------------------------- |
| 401         | UNAUTHORIZED | 로그인하지 않은 상태로 접근                                                            |
| 400         | BAD_REQUEST  | 패치 받기 미완료 상태에서 입장 시도                                                    |
| 400         | BAD_REQUEST  | 입장 기록이 없는 상태(입장 시각 만료 등)에서 신호 전송 → 프론트는 입장 API를 다시 호출 |

**구현 메모 (백엔드 담당, 착수 시 참고)**

- **역할 분담**: 인원 집계와 입장 시각 저장은 백엔드, 신호 전송·스톱워치 표시·화면 이동은 프론트(웹)가 담당한다. 다른 사용자가 방에 있는지는 서버만 알 수 있기 때문이다.
- **왜 신호(하트비트)가 필요한가**: 서버는 응답을 보낸 뒤 사용자가 아직 페이지에 있는지 알 수 없다. 네트워크 끊김·브라우저 강제 종료 시에는 퇴장 요청이 오지 않으므로, "아직 있다"는 신호를 주기적으로 받고 끊기면 떠난 것으로 본다. 퇴장 API는 바로 빼주는 보조 수단이다.
- **API 3개** (인원 조회 API는 따로 두지 않는다)

| API  | 메서드 | 하는 일                                                                   | 응답                 |
| ---- | ------ | ------------------------------------------------------------------------- | -------------------- |
| 입장 | POST   | 사전조건 검사, 입장 시각 저장(10분 내 재입장이면 기존 값 유지), 신호 기록 | 현재 인원, 입장 시각 |
| 신호 | PUT    | 30초마다 호출, 신호 시각 갱신                                             | 현재 인원            |
| 퇴장 | DELETE | 인원에서 즉시 제외                                                        | 없음                 |

- **Redis 구조**
    - 접속자: ZSET `interaction:rest-room:members` 하나에 member=userId, score=마지막 신호 시각(epoch ms)으로 `ZADD`. 인원은 `ZCOUNT`로 최근 60초 이내 score만 세고, 오래된 항목은 `ZREMRANGEBYSCORE`로 정리한다. 퇴장 시 `ZREM`.
    - 입장 시각: `interaction:rest-entered:{userId}`. 입장·신호 때마다 TTL을 10분으로 갱신한다. 마지막 신호(또는 퇴장) 후 10분이 지나면 사라지므로, 그 안에 재입장하면 스톱워치가 이어진다.
    - 사용자별 키 + TTL 60초 방식은 저장은 쉽지만 인원을 세려면 Redis 키 전체를 훑어야(`KEYS`/`SCAN`) 해서 쓰지 않는다.
- **프론트 동작**
    - 페이지를 떠날 때(`pagehide`) `fetch(url, { keepalive: true })`로 퇴장 API를 호출한다. `navigator.sendBeacon`은 `Authorization` 헤더를 붙일 수 없어 JWT 인증이 안 되므로 쓰지 않는다.
    - 다른 탭으로 전환해 페이지가 숨겨지면(`visibilitychange`) 신호를 멈추고 퇴장, 다시 보이면 입장 API를 호출한다. 크롬은 오래 숨겨진 탭의 타이머를 1분 간격으로 늦춰 인원 숫자가 깜빡이기 때문이다. 10분 안에 돌아오면 입장 시각이 유지된다.
    - 스톱워치는 브라우저 시간이 아니라 입장 응답의 입장 시각부터 계산한다(새로고침해도 이어짐).
