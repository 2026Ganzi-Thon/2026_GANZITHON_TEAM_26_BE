# ITR-MAP 기능 명세

## ITR-MAP-001 온기 지도 인원 표시

> "지금 같은 마음"과 "지금은 조용한 시간이에요"는 하나의 실시간 집계가 아니라 서로 다른 두 시간 범위 조회입니다. ① 최근 24시간 이내 집계, ② 24시간 초과~7일 이내 집계를 각각 쿼리해서, ①이 있으면 ①을, 없으면 ②를, 그마저 없으면 '첫 빛'을 보여주는 순서로 구현해야 합니다.

**트리거**
온기 지도 화면 진입

**사전조건**
로그인 상태, 최근 24시간 이내 기록 1건 이상

**입력**
없음 (최근 24시간 이내 고른 감정 기준)

**처리 로직**

1. 실시간 연결 상태 확인, 끊기면 상단 배너로 마지막 인원을 유지(재연결 시 자동 갱신)
2. 최근 24시간 이내 기록에서 고른 감정을 전부 모아, 감정별로 각각 독립적으로 인원을 집계한다. 한 기록에 감정이 여러 개 담겨 있거나 여러 번 기록해 감정이 2개 이상이면, 감정마다 별도의 집계·문구를 보여준다(같은 사람이 두 감정 모두에 포함되는 overlay를 허용하며, 감정 간 합산은 하지 않는다). 각 감정 집계 내에서는 유저 ID 기준 중복 없이 센다.
3. 최근 24시간 이내 같은 마음을 고른 인원이 있으면 "지금 N명이 같은 마음" 표시(정확한 인원 수를 내려준다, 감정이 2개 이상이면 감정마다 따로 표시)
4. 최근 24시간 이내는 없고, 24시간 초과~7일 이내 인원이 있으면 "지금은 조용한 시간이에요" + 지난 7일 인원 표시
5. 지난 7일에도 없으면(나뿐이면) "첫 빛" 문구 표시
6. 오늘 4번째 이상 기록이면 담요 미적립 안내를 추가 표시
7. 지도 집계용 기록(유저 ID·감정·시각)은 7일이 지나면 집계값만 남기고 삭제하는 게 맞지만, 그 정리 배치([[SYS-DATA-001]])는 추후 구현(P2)이라 지금은 원본이 계속 보관된다. 이 조회 로직 자체는 원본이 있든 집계값만 있든 동일하게 동작한다.

**출력**
인원 집계 문구, 담요 미적립 안내 여부

**예외 케이스**

| Status Code | Status Name           | Description                 |
| ----------- | --------------------- | --------------------------- |
| 401         | UNAUTHORIZED          | 로그인하지 않은 상태로 접근 |
| 400         | NO_RECENT_MOOD_RECORD | 최근 24시간 이내 기록 없음  |
| 500         | INTERNAL_SERVER_ERROR | 인원 집계 조회 실패         |

**구현 메모 (백엔드 담당)**

- **역할 분담**: 인원 집계(24시간/7일 범위 판단, 유저 ID 중복 제거)는 모두 백엔드에서 한다. 다른 사용자의 기록은 서버만 알 수 있기 때문이다. 프론트(웹)는 API 호출, 받은 값으로 문구 그리기, 연결 끊김 배너만 담당한다.
- **24시간 경과 처리**: 24시간 뒤에 기록을 빼는 타이머·삭제 작업은 만들지 않는다. 조회할 때마다 `created_at >= LocalDateTime.now(clock).minusHours(24)` 조건으로 센다. 24시간이 지난 기록은 QUIET(24시간 초과~7일) 판단에 쓰이므로 지우면 안 된다([[SYS-DATA-001]]).
- **"오늘 고른 감정"도 24시간 기준**: 사전조건·처리 로직 2번에서 말하는 "최근 24시간 이내 고른 감정"은 "오늘"(자정 기준) 하루 중 가장 최근 기록 1건이 아니라, `recordedAt`이 `now.minusHours(24)` 이후인 기록을 전부 모아 거기 담긴 감정을 합친 것이다. 자정이 지나도 24시간 안이면 이어서 집계되고, 하루에 여러 번 기록했다면 그 전 기록의 감정도 빠지지 않는다. 담요 미적립 안내(처리 로직 6번)만 자정 기준 "오늘" 횟수(`DailyStat.pickCount`)를 그대로 쓴다 — 담요는 하루 단위로 쌓이는 것이라 자정 기준이 맞다.
- **기록 있음 판정의 단일 기준**: 사전조건 "최근 24시간 이내 기록 1건 이상"은 `MoodRecord`의 `recordedAt`이 24시간 이내인지 하나로만 판단한다(`DailyStat.pickCount` 등 다른 테이블로 중복 확인하지 않는다). 두 기준이 따로 있으면 어긋났을 때 어느 쪽을 믿어야 할지 애매해지기 때문이다.
- **인원 수 표시**: `paths/ITR-MAP.yaml`의 `EmotionCount.count`는 정확한 정수를 그대로 내려준다.
- **갱신 방식**: WebSocket 같은 실시간 연결 없이 화면 진입 시 1회 조회하고, 필요하면 프론트가 1분 간격으로 다시 조회한다. 처리 로직 1번의 "실시간 연결 끊김 배너"는 조회 실패 시 마지막 값을 유지한 채 배너를 띄우는 것으로 대체한다.
