## BLK-SEND-001 보내기 가능 확인

**트리거**
보내기 화면 진입(보내기 탭 또는 한 올 받기 화면에서)

**사전조건**
로그인 상태

**입력**
없음

**처리 로직**
1. 오늘 보낼 수 있는 개수(발송권) 확인, 0개면 발송 불가 안내
2. 통과 시 작성 화면 표시, 대상 감정별 질문 목록(부족한 마음 우선 노출)도 함께 제공

**출력**
작성 가능 여부, 오늘 보낼 수 있는 개수, 감정별 질문 목록, (개수 소진 시) 안내 메시지

> 오늘 보낼 수 있는 개수는 자정 기준으로 매일 5개 지급되고, 마음 기록 저장([[CRD-WRITE-003]]) 시 사연이 포함되어 있으면 1개씩 추가 지급된다(쌓이는 개수에 상한 없음). 쿨타임은 없으며, 발송에 성공할 때마다 1개씩 차감한다.
>
> 발신자가 신고를 누적해 보내기 자체가 제한되는 건 [[BLK-RPT-002]](추후 구현, P1)의 몫이라 지금은 이 확인에 포함하지 않는다. BLK-RPT-002가 구현되면 그때 이 처리 로직에 제한 확인 단계가 추가된다.

**예외 케이스**

| Status Code | Status Name | Description |
| --- | --- | --- |
| 401 | UNAUTHORIZED | 로그인하지 않은 상태로 접근 |
| 429 | TOO_MANY_REQUESTS | 오늘 보낼 수 있는 개수 소진(0개) |

## BLK-SEND-002 한 올 검사·발송

**트리거**
작성 화면에서 '보내기' 클릭

**사전조건**
로그인 상태, 오늘 보낼 수 있는 개수 1개 이상

**입력**
- `targetEmotion` (string): 대상 감정, 필수 (BLK-SEND-001에서 받은 질문 목록 중 선택)
- `content` (string): 1~50자, 필수 (대상 감정 질문에 대한 답 — 템플릿 선택 또는 직접 작성)

**처리 로직**
1. 1차 금칙어(단어) 필터 통과 여부 확인
2. 2차 AI 분류로 위기/부적절/정상 판별([[ALRT-DETECT-001]] 연동)
3. 위기 판정 시 발송 보류, 작성 글 삭제 후 위기 안내 화면([[ALRT-HELP-002]])으로 이동
4. 부적절 판정 시 사유 안내와 함께 수정 요청, 작성 내용 유지
5. 정상 판정 시 발신자 해시(HMAC)와 함께 대기열에 등록, 대기 순서는 등록 시각 기준
6. 발송 완료 시 하루 집계([[SYS-STAT-001]])에 보낸 개수 반영, 오늘 보낼 수 있는 개수 1개 차감 — 남은 개수가 1개일 때 '보내기'를 거의 동시에 두 번 보내는 등 동시 요청이 겹쳐도 둘 다 성공해 개수가 음수로 내려가지 않도록, 차감은 "남은 개수 > 0일 때만" 조건과 함께 원자적으로 처리하고 조건을 만족 못하면 429로 처리한다.

**출력**
발송 완료 여부(정상) / 수정 요청 사유(부적절) / [[ALRT-HELP-002]] 위기 안내 화면 이동 안내(위기)

> 위기 표현 감지는 예외가 아닌 정상 분기로, 200 응답 후 위기 안내 화면([[ALRT-HELP-002]])으로 안내합니다.

**예외 케이스**

| Status Code | Status Name | Description |
| --- | --- | --- |
| 401 | UNAUTHORIZED | 로그인하지 않은 상태로 접근 |
| 400 | BAD_REQUEST | 본문 길이 0자 또는 50자 초과 |
| 400 | BAD_REQUEST | 대상 감정 미선택 |
| 400 | BAD_REQUEST | 1차 금칙어 필터 걸림 / 2차 AI 분류 부적절 판정 |
| 429 | TOO_MANY_REQUESTS | 오늘 보낼 수 있는 개수 소진(0개) |
| 500 | INTERNAL_SERVER_ERROR | 서버 전송 실패(작성 내용 유지) |
